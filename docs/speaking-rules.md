# 角色发言规则分析

> 代码：`backend/app/agent/group.py`（`select_speakers` / `score_member`）
> 配置：`backend/app/core/config.py` 的 `GROUP_*`
> 数据：实测书架「龙族大家庭」，42 名成员

---

## 0. 一句话

**发言规则分两层：一层决定「谁说话」（打分 + 阈值），一层决定「怎么说」（提示词约束）。**
第二层没问题，**第一层的阈值和真实数据是脱节的**——详见 §3。

---

## 1. 谁说话：打分公式

```
score = 0.30 × 外向度
      + 0.25 × 相关性
      + 0.15 × 情绪唤醒(arousal)
      + 0.10 × 噪声(±1)

修正项：
  相关性 ≥ 0.7      → +0.10（被点名的人更愿意接）
  冷却中(<45s)      → -0.20
  上一句就是他说    → -0.15
```

**外向度**由性格关键词映射（`SPEECH_RULES`，命中第一条即返回）：

| 性格关键词 | 外向度 | 果断度 |
|---|---:|---:|
| 热情 / 开朗 / 活泼 / 话多 / 健谈 / 直爽 | 0.85 | 0.70 |
| 温柔 / 温和 / 善良 / 体贴 / 耐心 | 0.60 | 0.45 |
| 天真 / 单纯 / 烂漫 | 0.70 | 0.50 |
| 暴躁 / 易怒 / 冲动 | 0.80 | 0.85 |
| 傲慢 / 自负 / 高傲 | 0.65 | 0.75 |
| 冷静 / 克制 / 理性 / 沉稳 | 0.45 | 0.50 |
| 多疑 / 警惕 / 谨慎 / 敏感 | 0.40 | 0.55 |
| 寡言 / 沉默 / 话少 / 冷淡 / 疏离 | 0.25 | 0.35 |
| **都不命中** | **0.50** | 0.50 |

**相关性**（`_relevance`）——只认三件事：

| 情况 | 分值 |
|---|---:|
| 名字出现在这句话里 | 0.9 |
| 别名出现 | 0.7 |
| 他关系里的人出现 | 0.4 |
| 都没有 | 0.0 |

## 2. 四条入选路径（按优先级）

```
① 显式 @            → 必答，跳过阈值和冷却，分数记 1.0，理由"被 @"
      ↓ 没有 @
② @全体成员          → 阈值降到 0.18
      ↓ 也不是 @全体
③ 按分数排序，过 0.30 的入选（最多 max_speakers=2）
      ↓ 一个都没过线
④ 兜底：让分最高的那位接一句（GROUP_ALWAYS_REPLY=true，默认开）
```

**前置过滤**：`status ∈ {online, active}` 且 `state ≠ muted`。
`@全体成员` 会先把所有人 `status` 置 `online`（顺带 `left_at=NULL`），再走 ①。

## 3. 实测：阈值和真实数据对不上

### 3.1 默认性格的角色够不着阈值

42 名成员里，**绝大多数没命中任何性格关键词**（personality 字段为空或不在词表里），
全部落到默认外向度 0.5。代入公式：

```
期望分 = 0.30×0.50 + 0.25×0 + 0.15×0.35 + 0
       = 0.150    +    0  + 0.0525
       = 0.2025          ← 阈值 0.30
```

**0.2025 < 0.30，差 0.0975。** 噪声范围是 ±0.10，也就是说：
**默认角色只有落在这 10% 噪声的上半区（约 33% 概率）才可能过线。**

| 外向度 | 无关时的期望分 | 过 0.30？ |
|---:|---:|:---:|
| 0.25（寡言） | 0.128 | ✗ |
| 0.45（冷静） | 0.188 | ✗ |
| **0.50（默认）** | **0.2025** | **✗** |
| 0.60（温柔） | 0.232 | ✗ |
| 0.85（热情） | 0.307 | ✓ 勉强 |

**只有「热情 / 暴躁」这两类能稳定自发开口。** 其余所有人，不 @ 就永远不够。

### 3.2 于是「谁说话」实际上由随机数决定

实测「今天好累啊」（无 @）：

```
入选: 小山隆造 (0.301, "外向0.50")
      雷娜塔   0.129 ✗
      零号     0.129 ✗
      陈雯雯   0.129 ✗
```

`0.301` 里有多少是真实意愿？把噪声拆开看：

```
0.150(外向) + 0.0525(arousal) = 0.2025
0.301 - 0.2025 = 0.0985   ← 几乎全是噪声
```

**换句话说：谁接话，基本是随机的。** 42 人里分数从 0.10 到 0.30 均匀分布，
每次抽一个人。用户感受到的「群里总有人回」是兜底机制在工作，
而不是「最合适的人在回」。

### 3.3 `@全体成员` 绕过了 `max_speakers`

`group.py:250` 那一段是这么写的：

```python
# 不受 max_speakers 限制、也不看阈值（用户要的就是"都回一句"）
if all_called:
    for member in usable:
        everyone.append(...)
    return everyone        # ← 42 个人全返回
```

但同一个函数的 docstring 写的是：

> `@全体成员` 把阈值降到 `all_threshold`，但仍受 `max_speakers` 限制

**文档和代码矛盾。** 实测：

```
max_speakers=2，但 @全体 实际选出 42 人
=> 并行 fan-out 会同时发起 42 次模型调用
```

这是我上一轮加 `Send` 并行**放大**了的问题：以前是串行 42 次（慢但稳），
现在是 42 个请求同时打出去——容易撞限流，账单也难看。

## 4. 冷却与惩罚

| 机制 | 依据 | 作用 |
|---|---|---|
| 冷却 45s | `last_spoke_at`，由 `record_member_spoke` 写入 | 分 -0.20，刚说过的人不容易再开口 |
| 刚说过 | `last_speaker_id` 等于自己 | 分 -0.15 |
| 静音 | `state = 'muted'` | 直接从候选里剔除 |

**一个数据问题**：`state` 只在发言时被写成 `'cooldown'`，
而**全项目没有任何地方把它改回 `'idle'`**（只有 `muted → idle` 的恢复）。

实测 42 名成员的状态：

```
{('online', 'cooldown')}   ← 42 人全是这个
```

因为候选过滤只看 `≠ muted`，所以不影响发言；
但界面上的「冷却中」是**永久的**，等于这个状态字段没有信息量。

真正起作用的冷却是 `last_spoke_at` + 45 秒，这个是对的。

## 5. 怎么说：发言内容规则

选定人之后，每个发言人拿到的约束（`chat.py` + `dialogue.plan`）：

```
你在群聊里，用「{名字}」的身份说话：**只说 1 句，最多 2 句短话**；
不要写动作、神态、心理描写，不要复述别人说过的话。

【群聊上下文，最近几条】
用户：...
沈砚：...

【本轮判断（内部参考，不要说破）】
用户情绪：疲惫（强度 0.4）｜意图：倾诉
【应对策略】
- 以共情为主，别急着给方案
...
```

要点：

- **字数**：1~2 句（比单聊更短）
- **不写旁白**：和单聊同一条规则
- **能看到前面的人**：`transcript` 累积（**但并行时看不到同批的人**）
- **带 SOP**：和单聊同一套 `dialogue.plan` 输出
- **后置校验**：`dialogue.verify` 会在 `speaker_end` 前改写（去说教 / 安全兜底）

## 6. 问题清单

按严重度排：

| # | 问题 | 影响 | 位置 |
|---|---|---|---|
| 1 | **阈值 0.30 高于默认角色期望分 0.2025** | 非 @ 场景"谁说话"由噪声决定，沦为随机 | `group.py:186` + `config.py:group_speak_threshold` |
| 2 | **`@全体成员` 绕过 `max_speakers`** | 42 人并行调用，限流与成本风险 | `group.py:246-266` |
| 3 | `state` 只在发言时置 `cooldown`，永不复位 | 界面"冷却中"永久显示，字段失去意义 | `database.py:2000` |
| 4 | 性格词表覆盖窄，大多数角色落默认 0.5 | 42 人里几乎没有差异，分数趋同 | `group.py:52` |
| 5 | 相关性只认名字/别名/关系名 | "有人吗""说点什么"这类话对所有人都是 0 相关 | `group.py:136` |
| 6 | 兜底永远选分最高者，但分高≈噪声大 | 兜底语义失真（本意是"最想说的"） | `group.py:335` |

## 7. 建议

**最小改动（改一个数就能缓解 #1）：**

```python
group_speak_threshold: float = 0.30  →  0.15
```

0.15 低于默认期望 0.2025，普通人能过线，寡言的人（0.128）仍然不该过线——
这才符合"谁相关谁说话"的直觉。

**其他三条：**

| 问题 | 建议 |
|---|---|
| #2 `@全体` 爆炸 | 在 `all_called` 分支加 `[:max_all_speakers]`（新配置，默认 5~8），并保留"随机抽"而不是全量 |
| #3 状态不复位 | 加一个 `refresh_member_states()`：`last_spoke_at` 超过冷却期就把 `cooldown` 改回 `idle`，在 `ensure_shelf_members` 里顺手调用 |
| #4 词表太窄 | 抽取阶段就把性格规整到词表内；或对未命中的角色按 `turns`/历史发言数微调外向度 |
| #5 相关性太窄 | 加规则词：`有人/在吗/大家/谁/说点什么` → 全员相关性 +0.2（但不顶到 0.7 的"被点名"档） |
| #6 兜底失真 | 改为"分最高且不在冷却"的那位，并把噪声权重从 0.10 降到 0.05 |

---

## 8. 一句话总结

> **发言内容规则（短句、不说教、带 SOP）是合理且经过校验的；
> 发言者选择规则的阈值与数据脱节——0.30 的门槛下，42 个角色里只有约 1/3 的人
> 在 33% 的概率下靠噪声过线，于是「谁说话」实际上变成了抽签。**
>
> 把阈值调到 0.15、给 `@全体` 加人数上限，这两个改动就能让规则重新符合直觉。
